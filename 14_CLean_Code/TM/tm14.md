# TM14 - Refaktorisasi Kode

## Tujuan

Melakukan refaktorisasi kode agar lebih mudah dibaca, dipelihara, dan sesuai dengan prinsip Clean Code.

## Masalah pada Kode Awal

Beberapa masalah yang ditemukan:

1. Fungsi terlalu panjang.
2. Memiliki banyak tanggung jawab sekaligus.
3. Sulit untuk diuji.
4. Sulit dipelihara ketika aplikasi berkembang.
5. Manipulasi DOM, pengambilan data, dan event handling berada dalam satu fungsi.

## Solusi Refaktorisasi

Kode dipecah menjadi beberapa fungsi kecil:

* `fetchOrder()` untuk mengambil data pesanan.
* `displayOrder()` untuk menampilkan detail pesanan.
* `setupCloseButton()` untuk menangani tombol tutup modal.
* `setupConfirmButton()` untuk menangani tombol konfirmasi.

Dengan pendekatan ini setiap fungsi hanya memiliki satu tanggung jawab (Single Responsibility Principle).

## Keuntungan

1. Kode lebih mudah dibaca.
2. Lebih mudah melakukan debugging.
3. Lebih mudah melakukan testing.
4. Lebih mudah dikembangkan di masa depan.
5. Mengurangi duplikasi kode.

## Kesimpulan

Refaktorisasi membuat kode menjadi lebih bersih, modular, dan mudah dipelihara. Setiap fungsi memiliki tanggung jawab yang jelas sehingga kualitas kode meningkat.
